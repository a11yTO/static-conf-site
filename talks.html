Smells Like Shift Spirit

Smells Like Shift Spirit cranks accessibility up from background noise to the main stage. If your team has been stuck in the “Shift Left” grunge era, all distortion, no distribution, this session shows you how to tune up, plug in, and actually play together. We’ll break down why old approaches fell flat, introduce a more collaborative “Shift Out” sound, and give every role in your org three concrete moves they can start riffing with on Monday. No theory solos, no compliance ballads, just practical, loud‑and‑clear accessibility you can feel. Come ready to turn the amps up. We're going to 11!

Beyond The <div>: Elevating React Testing Library (RTL) Tests with Accessible, Semantic Markup

Why do so many unit tests rely on brittle test IDs or complex text queries? The secret to resilient tests lies in the bedrock of the web: semantic HTML. When we build with the right HTML elements, we inherently construct a robust accessibility tree that React Testing Library (RTL) can leverage.

Beyond the DOM: Understanding the Accessibility Tree

Many developers inspect the DOM (Document Object Model), but users using assistive technologies never actually interact with the DOM directly. In this session, we'll explore the browser's accessibility tree (in Chrome), how it is generated from HTML, CSS, and ARIA, and how it shapes the experience of screen reader users. Attendees will learn how to inspect accessibility trees in modern browser developer tools and gain a deeper understanding of how browsers communicate accessibility information.

The Secret Life of Bugs

Not all bugs crash a game. Some quietly shape who gets to play. In modern game development, QA has become highly effective at identifying functional failures, issues that break systems, block progression, or violate defined requirements. But many accessibility issues don’t present this way. They live in the space between “working as designed” and “working for players.”

This talk explores the “secret life” of these issues, reframing accessibility not as a compliance layer or a checklist, but as a critical lens for evaluating product quality. Attendees will leave with a practical framework for identifying accessibility gaps earlier, integrating player-centered validation into QA and product workflows, and treating accessibility signals with the same rigor as traditional bugs. Because if the system works, but the player can’t, it’s still broken.

This Is Why We Can't Have Nice Themes (Modern CSS for Accessible Colors)

Accessible color systems often start with the best intentions: dark mode, high-contrast themes, and user preferences. But every new inclusive feature tends to pile on extra variables, manual contrast checks, and complex media query overrides. Before long, the architecture becomes so fragile and bloated that it breaks under its own weight … this is why we can’t have nice themes.

Thankfully, modern browser engines can now handle much more heavy lifting. This practical, code-rich session will walk through real-world component refactors that prune redundant code, improve performance for all users, and make resilient, high-contrast interfaces much easier to support over the long term.

How Low Can You Go? Accessibility Before and After POST.

Most accessibility work begins once an operating system, desktop environment, or application is already running. But computers start much earlier than that.

This talk explores accessibility across the boot chain, from power-on and firmware through bootloaders and into the operating system. Drawing from practical work bringing text-to-speech to UEFI environments, we'll examine what accessibility infrastructure exists today, where critical gaps remain, and what it would take to make computing accessible from the moment a machine is turned on.

Attendees will gain an introduction to low-level accessibility, firmware and bootloader challenges, and opportunities for future work below the application layer.

The Aesthetic-A11y Paradox: Taming the Visual Prowess of Modern LLMs for Born-Accessible Code

Modern Large Language Models (LLMs) have developed a sophisticated eye for visual design. However, this rapid advancement in visual styling capabilities introduces a new engineering challenge: the Aesthetic-A11y Paradox. When models focus heavily on achieving rich visual presentation, the underlying semantic markup and keyboard interactions can sometimes be overlooked.

In this talk, we share insights from a longitudinal study of 99 distinct UI components generated across 20 rounds of AI model iterations. We will analyze how default model outputs behave when balancing complex visual designs (such as gradients, custom interactive widgets, and complex grids) against core WCAG criteria.
